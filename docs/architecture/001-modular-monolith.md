# Модульный монолит WBai

## Решение

Приложение остаётся одним процессом Express и одной PostgreSQL-базой. HTTP-контракты, пути и JSON-ответы не версионируются и не меняются. `server.js` является только точкой запуска; сборка приложения размещена в `src/`.

## Границы слоёв

- `config/` — обязательная проверка окружения и неизменяемая конфигурация.
- `middleware/` — аутентификация, лимиты и политики HTTP, валидация, request id, единая передача async-ошибок.
- `routes/` — объявление URL и порядок middleware; бизнес-логики нет.
- `controllers/` — HTTP-ввод и точные формы ответов.
- `services/` — сценарии приложения: auth, шаблоны, кредиты.
- `repositories/` — SQL и преобразование результатов PostgreSQL.
- `migrations/` — идемпотентная исходная миграция и таблица `schema_migrations`.
- `legacy/` — временный адаптер ещё не вынесенных API. Он использует общие middleware, конфигурацию и сервис резервирования кредитов.

## Перенос без изменения интерфейса

1. Перенесены config, инфраструктурные middleware, миграции, static, auth и templates.
2. P0-правила (строгий CORS, security headers, allow-list image-proxy, admin guard, атомарный reserve кредитов) подключены до legacy-маршрутов и сохранены.
3. Следующими вертикальными срезами должны быть `admin`, `wildberries`, `infographics`, `analytics`; каждый переносит route → controller → service → repository в одном изменении.
4. После переноса последнего среза `legacy/app.js` удаляется. Разделять процесс или базу данных не требуется.

## Наблюдаемость и ошибки

Каждый ответ получает `X-Request-Id`; лог запроса и ошибок выводится JSON и не включает ключи, токены, пароли или base64-изображения. Любой `async`-обработчик передаёт исключение в единый error handler; клиенту выдаётся стабильная JSON-ошибка без деталей внутренней ошибки.
